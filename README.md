# Распределение дефицита

Один шаг модуля SNP Heuristic: доступного объёма меньше, чем просят заявки. Проект решает, кто и сколько получит по одной позиции в одном периоде, и печатает, сколько осталось нераспределённым.

## Что делает расчёт

`run.py` читает `data/supply.csv` и `data/requests.csv`. Кейсы с одной и той же парой `item` + `source_location` делят общий запас. Сначала каждый кейс забирает свою квоту, не больше собственного `available_qty` и не больше остатка склада. Затем общий остаток дораспределяется между заявками этой позиции.

Результат пишется в `output/shipments.csv` и печатается в консоль. Сначала таблица отгрузок, затем сводка нераспределённого остатка по позиции и источнику.

Жёсткие ограничения результата:

1. Отгрузка заявке либо `0`, либо количество не ниже `min_lot` и кратное шагу.
2. Повторный запуск на тех же файлах даёт тот же план.
3. Шаг отгрузки — `rounding_value`. Ноль означает шаг `1`.

Сумма отгрузок одного кейса может превысить его `available_qty`: невыбранный из-за кратности остаток соседа остаётся на общем складе и уходит в поздние проходы другого кейса.

## Входные данные

`data/supply.csv` — доступный объём.

| Поле | Смысл |
| --- | --- |
| `case_id` | Независимый тест-кейс на входе. На складе кейсы одной позиции сливаются |
| `period` | Период, `YYYY-MM`. Читается и на план не влияет |
| `item`, `source_location` | Что и откуда отгружаем. Ключ общего запаса |
| `available_qty` | Сколько единиц доступно к отгрузке в этом кейсе |

`data/requests.csv` — заявки на этот объём.

| Поле | Смысл |
| --- | --- |
| `case_id` | К какому кейсу относится заявка |
| `request_id`, `dest_location` | Кто просит |
| `priority` | Приоритет. `1` — наивысший |
| `demand_qty` | Сколько запрошено |
| `min_lot` | Минимальная партия. `0` — ограничения нет |
| `rounding_value` | Кратность отгрузки |

Отрицательные количества в CSV берутся по модулю. Заявка, для которой нет строки запаса, пропускается и пишется в лог как ошибка.

## Правило

Приоритет жёсткий. Сначала все заявки с приоритетом `1`, затем `2` и дальше. Внутри одного приоритета объём идёт по кругу шагами кратности. Порядок в круге — по `request_id`. Полные круги считаются делением бюджета на сумму шагов, а не циклом по каждой единице.

Проходы по общему остатку, после квот кейсов:

1. Добор до `min_lot`. Спрос можно перешагнуть, иначе минимум выше `demand_qty` недостижим.
2. Добор до спроса шагами, которые спрос не перешагивают.
3. Покрытие спроса. Последний шаг может перешагнуть `demand_qty`, чтобы попасть в кратность.
4. Остаток поровну, без приоритета. База укладывается вниз до кратности, хвост круга начинается с большего `request_id`.

После проходов партия меньше `min_lot` или не кратная шагу обнуляется и возвращается в нераспределённый остаток.

## Запуск

Нужны Python 3.12 и Poetry.

```sh
poetry install
poetry run python run.py
```

Одна команда расчёта — вторая. Она читает CSV из `data/` и обновляет `output/shipments.csv`.

## Тесты и линт

```sh
poetry run pytest
poetry run ruff format . --check
poetry run ruff check .
```

Тесты фиксируют план на CSV из `data/` и два собственных случая: старший приоритет забирает бюджет раньше меньшего спроса, а `min_lot` второго кейса добирается из невыбранной кратности первого.

На пуше в `main` и на pull request GitHub Actions запускает только Ruff и pytest.

## Структура

| Путь | Смысл |
| --- | --- |
| `run.py` | Точка входа |
| `app/allocation.py` | Квоты, минимальные партии, спрос, хвост |
| `app/report.py` | Таблица отгрузок и нераспределённый остаток |
| `app/schemas.py` | Строки CSV |
| `app/utils.py` | Чтение CSV и таймер |
| `config/logging.yaml` | Консоль и `LOGGING.LOG` |
| `data/` | Входные кейсы |
| `tests/test_allocation.py` | Проверка плана |

## Логи

Уровень логгера `app` — `DEBUG`, поэтому в консоли видны и таймеры.

- `DEBUG` — длительность чтения CSV, расчёта и записи отчёта.
- `INFO` — операция завершилась: данные прочитаны, квоты, минимальные партии, добор и покрытие спроса, равный хвост, проверка партий, отчёт записан.
- `WARNING` — партия снята, потому что не проходит `min_lot` или шаг.
- `ERROR` — у заявки нет запаса, либо шаг упал с исключением. Исключение пишется со стеком и пробрасывается дальше.

В `LOGGING.LOG` попадают только `INFO` и выше. Файл в UTF-8.
